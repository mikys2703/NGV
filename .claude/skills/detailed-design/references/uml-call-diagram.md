# 상세설계 다이어그램 — UML 호출관계

조직 실제 템플릿: `WP_Templates/Engineering/SoftwareDetailedDesignAndUnitConstruction/TPL-SWE3-002_상세설계 UML 및 호출관계 템플릿.drawio` (draw.io 형식). `architecture-design` 스킬과 동일하게 draw.io 기준이며, 뼈대(시스템/설계 경계, 외부 액터, 대상 요소, 관계)도 동일한 구조를 재사용합니다.

## 이 템플릿만의 작성 안내 (아키텍처 UML과의 차이)

아키텍처 다이어그램이 컴포넌트/인터페이스 수준이라면, 이 다이어그램은 그 안의 구현 단위 수준입니다. 템플릿의 작성 안내 4가지:

1. **구현 단위와 책임** — 모듈/클래스/함수 단위로, 아키텍처 요소보다 한 단계 더 세분화
2. **함수 또는 클래스 호출** — 호출 방향과 순서 (시퀀스 다이어그램 또는 클래스 다이어그램의 연관/의존 관계)
3. **입력 출력 자료형** — 각 호출에 오가는 데이터의 타입 (함수 계약과 일치시킬 것, `contracts-and-decision-tables.md`)
4. **설계 및 시험 추적 ID** — 이 단위가 어떤 상세설계 ID/단위시험 ID와 연결되는지 (`traceability-unit.md`)

## 다이어그램 종류 선택

| 표현 대상 | 다이어그램 |
|---|---|
| 모듈/클래스 구조와 정적 관계 | 클래스 다이어그램 |
| 함수 호출 순서, 요청-응답 흐름 | 시퀀스 다이어그램 |
| 알고리즘의 분기/반복 로직 | 액티비티 다이어그램 또는 흐름도 (의사코드와 병행 가능) |
| 상태전이 상세(8장) | 상태 머신 다이어그램 |

## 일관성 요구사항

다이어그램의 요소 ID·함수명은 본문(2~8장)의 표기와 **글자 그대로** 일치해야 합니다. 또한 이 다이어그램의 요소는 상위 `architecture-design` 스킬로 만든 아키텍처 다이어그램의 컴포넌트 ID를 거슬러 올라갈 수 있어야 합니다 — 상세설계 다이어그램만 봐서는 어느 아키텍처 요소에 속하는지 알 수 없다면, 요소 ID에 상위 컴포넌트 ID를 접두어로 포함시키는 등 연결 고리를 남기세요(예: `CMP-003.함수명` 또는 `CMP-003-UNIT-01`).

완성 파일은 `ENG-SWE3-002_상세설계 UML 및 호출관계 원본.drawio`로 저장합니다.
