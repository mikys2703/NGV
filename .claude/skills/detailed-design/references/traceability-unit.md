# 추적성 — 아키텍처 · 상세설계 · 코드 · 단위시험

조직 추적 매트릭스는 `TPL-TRC-001_양방향 요구사항 추적 매트릭스 템플릿.xlsx`(산출물 ID `ENG-TRC-001`)이며, 열 구성은 다음과 같습니다: **Upper Req | SW Req | Architecture | Detailed Design | Code | SWE.4 | SWE.5 | SWE.6 | Coverage**. 이 스킬은 그중 **Architecture → Detailed Design → Code → SWE.4** 구간을 채우는 책임을 집니다.

## 채우는 방법

1. 모듈 분해(템플릿 2장)에서 만든 각 구현 단위 ID를 매트릭스의 "Detailed Design" 열 값으로 씁니다.
2. 그 단위가 구체화하는 아키텍처 요소 ID(architecture-design 스킬 산출물)를 "Architecture" 열에서 찾아 같은 행에 연결합니다 — 새 행이 필요하면 추가하고, 기존 아키텍처 요소 행이 있다면 그 행을 이어서 채웁니다.
3. 예정된 소스 파일/모듈 경로가 있다면 "Code" 열에 남깁니다(아직 코드가 없으면 "예정 경로"로 표시).
4. 이 단위를 검증할 단위시험 ID(아직 없다면 채번 후 "예정"으로 표시)를 "SWE.4" 열에 남깁니다.
5. 상위 요구사항(Upper Req/SW Req)까지 한 행에서 이어져야 하므로, 아키텍처 단계에서 이미 요구사항이 연결되어 있다면 그 값을 그대로 유지하고 새로 지어내지 마세요.

## 규칙

- 한 구현 단위가 여러 아키텍처 요소에 걸쳐 있다면(드물지만 발생 가능), 행을 나눠 각각 연결하세요 — 하나의 행에 여러 상위 요소를 욱여넣지 마세요.
- 상세설계 문서를 수정해 단위 경계가 바뀌면(단위를 나누거나 합치면), 매트릭스에서 옛 ID를 참조하던 행을 갱신하세요. ID를 재사용하지 말고(architecture-design 스킬의 추적성 규칙과 동일), 폐기된 단위는 결번으로 남깁니다.
- SWE.4 열이 계속 비어 있는 단위가 있다면, "핵심"으로 표시된 함수/알고리즘인데 검증 계획이 없다는 뜻이므로 SKILL.md 12단계 자가 점검에서 반드시 짚어내세요.

## 아키텍처 추적성과의 연결

`architecture-design` 스킬은 Upper/SW Req → Architecture 구간을 이미 채워뒀어야 합니다. 이 스킬은 그 뒤를 잇는 것이지 처음부터 다시 만드는 것이 아닙니다 — 매트릭스가 아직 없거나 비어 있다면, 상세설계를 계속하기 전에 아키텍처 산출물의 추적성이 먼저 채워져 있는지 확인하세요.
