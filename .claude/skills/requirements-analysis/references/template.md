# 요구사항 템플릿

## 현재 상태: 미확정 (사용자 제공 예정)

사용자가 실제로 사용할 요구사항 템플릿을 아직 전달하지 않았습니다. **사용자가 템플릿을 제공하면 이 파일을 그 템플릿 내용으로 즉시 교체하세요** — 아래 내용은 그 전까지 쓰는 임시 기본 양식입니다.

요구사항 작업을 시작할 때마다, 이 파일이 아직 임시 양식이라면 사용자에게 "아직 템플릿을 안 주셔서 임시 양식으로 작성합니다"라고 한 번은 알리세요.

## 임시 기본 양식 (IEEE/ISO 29148 스타일 기반)

요구사항 1건당 아래 속성을 표 또는 항목 형식으로 작성합니다.

| 필드 | 설명 |
|---|---|
| ID | `references/traceability.md`의 ID 체계에 따른 고유 식별자 |
| 유형 | 기능(Functional) / 비기능(Non-Functional, ISO 25010 품질특성 명시) |
| 문장 | EARS 패턴(`references/ears-clarity.md`)을 따르는 단일 SHALL 문장 |
| 근거/출처 | 이 요구사항이 왜 필요한지, 상위 요구사항 ID |
| 다이어그램 | 기능 요구사항인 경우 UML/SysML 다이어그램 (`references/uml-sysml.md`) |
| 수용기준 | 정량적, 측정 가능한 기준 |
| 검증방안 | 실행 가능한 방법(테스트/분석/검사/시연 중 하나 이상) + 검증 산출물 ID |
| ASIL | 안전 관련 요구사항인 경우 ASIL 등급(A/B/C/D) 또는 QM |
| 우선순위 | 필수/권고 등 |
| 상태 | 초안 / 리뷰중 / 합의 / 기준선(baseline) |

### 예시

```
ID: SYS-REQ-0012
유형: 기능
문장: WHEN 운전자가 도어 잠금 버튼을 누르면, THE 도어 잠금 시스템 SHALL 0.5초 이내에 모든 도어를 잠근다.
근거/출처: STK-REQ-0003 (사용자는 버튼 한 번으로 전체 도어를 잠글 수 있어야 한다)
다이어그램: [상태 다이어그램 링크/코드 블록]
수용기준: 버튼 입력 시점부터 모든 도어 액추에이터 완료 신호 수신까지 ≤500ms (10회 반복 측정 평균 및 최대값 기준)
검증방안: HIL 테스트 (TC-0045), 500ms 임계값에 대한 타이밍 분석 리포트
ASIL: B(D)
우선순위: 필수
상태: 초안
```

이 예시의 필드 이름과 순서는 사용자 템플릿이 도착하면 그대로 덮어써야 합니다.
