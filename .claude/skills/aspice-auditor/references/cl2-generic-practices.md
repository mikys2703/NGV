# CL2(관리되는 프로세스) — 일반관행(Generic Practice) 체크리스트

능력수준 2(CL2)는 CL1(PA1.1 프로세스 성과 — 해당 프로세스의 기본관행이 실제로 수행되어 정상적인 산출물을 만들어냈는지) 위에 두 개의 프로세스 속성을 추가합니다. CL2는 PA1.1을 대체하지 않습니다 — 오히려 전제조건입니다. PA1.1이 명백히 충족되지 않는다면(해당 프로세스의 기본관행/산출물 자체가 존재하지 않는다면) 그렇다고 명시하고, PA2.1/PA2.2가 아무리 좋아 보여도 CL2는 주장할 수 없다는 점을 밝히세요.

## PA 2.1 — 성과 관리(Performance Management)

*의도: 프로세스의 성과가 임의로 수행되는 것이 아니라 관리되고 있는가.*

| # | 일반관행 | 근거로 볼 것 |
|---|---|---|
| GP 2.1.1 | 프로세스 성과에 대한 목표가 식별되어 있다 | 프로세스에 대한 명시된 목표/목표치(예: 프로젝트/품질 계획서 내) — 막연한 회사 구호가 아니라 진척을 검증할 수 있을 만큼 구체적인 목표 |
| GP 2.1.2 | 프로세스의 성과가 계획되어 있다 | 해당 프로세스를 다루는 계획서: 일정, 활동, 마일스톤, 테일러링(tailoring) 결정 |
| GP 2.1.3 | 프로세스의 성과가 모니터링된다 | 상태보고서, 진척 추적, 실제로 시간에 걸쳐 수집된 지표/KPI(수집하기로 "계획"만 되어 있는 것이 아니라) |
| GP 2.1.4 | 프로세스의 성과가 계획에 맞춰 조정된다 | 모니터링에서 이탈이 확인되었을 때의 시정/예방 조치 근거 — 변경요청, 재계획 기록, 에스컬레이션 기록 |
| GP 2.1.5 | 프로세스 수행에 대한 책임과 권한이 정의되어 있다 | RACI, 역할 기술서, 해당 프로세스에 연결된 조직도, 지정된 담당자 |
| GP 2.1.6 | 프로세스 수행에 필요한 자원과 정보가 식별·제공·배정·활용된다 | 실제로 마련된 도구, 인력, 예산, 교육 기록, 템플릿/인프라 |
| GP 2.1.7 | 관련 당사자 간 인터페이스가 관리된다 | 커뮤니케이션 계획, 회의록, 부서 간 리뷰 기록, 실제로 사용된 에스컬레이션 경로 |

## PA 2.2 — 작업산출물 관리(Work Product Management)

*의도: 프로세스가 만들어내는 산출물이 단순히 존재하는 것을 넘어 제대로 식별·통제·리뷰되고 있는가.*

| # | 일반관행 | 근거로 볼 것 |
|---|---|---|
| GP 2.2.1 | 산출물에 대한 요구사항이 정의되어 있다 | 산출물이 만들어지기 전에 정의된 템플릿, 문서 표준, 내용/형식 요구사항 |
| GP 2.2.2 | 산출물의 문서화 및 통제에 대한 요구사항이 정의되어 있다 | 네이밍/버전 규칙, 형상관리(CM) 계획, 베이스라인/릴리스 기준 정의 |
| GP 2.2.3 | 산출물이 식별·문서화·통제된다 | 실제 버전 이력, 고유 ID, CM/변경 로그, 베이스라인/태그, 산출물별 추적 가능한 상태 |
| GP 2.2.4 | 산출물이 정의된 요구사항에 따라 리뷰되고 필요시 보완된다 | 리뷰/검사 기록, 승인 서명, 결함/코멘트 로그 및 그것이 종결되었다는 근거 |

## 판정 가이드

- 각 일반관행은 해당 프로세스/범위와 관련된 **모든** 산출물을 기준으로 판단하세요. 예시 하나만 보고 판단하지 마세요 — 리뷰 기록이 하나 잘 되어 있다고 해서 대부분의 다른 산출물에 리뷰 흔적이 없다면 GP 2.2.4가 프로젝트 전체에서 충족된 것은 아닙니다.
- "부분충족"은 흔하고 유용한 판정입니다 — 실제 프로젝트 대부분은 부분적인 근거만 가지고 있습니다(예: 계획은 있지만 모니터링이 없거나, 산출물은 버전관리되지만 공식 리뷰는 없는 경우). 실제로는 부분적인 상황을 굳이 충족/미충족의 이분법으로 강제하지 마세요.
- 동일한 근거 부족이 여러 일반관행에 걸쳐 반복된다면(예: "형상관리 관행 자체가 전혀 없음"이 GP 2.1.6과 PA2.2 전체 행에 동시에 영향을 준다면), 우선순위 조치 항목에서 행마다 반복 서술하지 말고 하나의 근본 원인으로 명확히 짚어주세요.
