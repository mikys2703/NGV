# 네이밍 규칙 — 함수명/변수명 3글자 이상, camelCase

이 프로젝트는 PEP8의 snake_case 관례 대신 **camelCase**를 명시적으로 채택했습니다(CLAUDE.md). 일반적인 "Pythonic" 스타일과 다르다는 것을 알고 있되, 이 프로젝트에서는 이 규칙을 따르세요 — 일반 관례로 되돌리지 마세요.

## 규칙

- 함수명, 변수명(매개변수 포함) 모두 camelCase: 첫 단어는 소문자로 시작, 이어지는 단어는 첫 글자만 대문자.
- 최소 3글자 이상. `i`, `n`, `ok`, `tmp` 같은 짧은 이름은 반복문 카운터라도 금지 — `idx`, `count`, `isOk`, `tempValue`처럼 3글자 이상으로 씁니다.
- 클래스명은 이 규칙의 적용 대상이 아닙니다(CLAUDE.md는 "함수명, 변수명"만 규정) — 클래스는 Python 표준 관례인 PascalCase를 그대로 씁니다.
- 상수(모듈 수준 불변값)에 대한 규정은 CLAUDE.md에 없습니다 — Python 관례상 `UPPER_CASE`를 쓰는 것이 일반적이며, 이 프로젝트에서 별도 지침이 없다면 그대로 유지하되 사용자가 다르게 요구하면 따르세요.

## 좋은 예 / 나쁜 예

| 나쁜 예 | 좋은 예 | 문제 |
|---|---|---|
| `x` | `speedKph` | 3글자 미만, 의미 없음 |
| `door_state` | `doorState` | snake_case (camelCase 위반) |
| `calc` | `calculateLockState` | 3글자는 넘지만 축약이 심해 의미 불명확(권장하지 않음) |
| `n` | `retryCount` | 3글자 미만 |
| `Get_Value` | `getValue` | 대문자 시작 + 밑줄 혼용 |

## 예외가 필요할 때

외부 라이브러리 인터페이스를 그대로 구현해야 해서 이름을 바꿀 수 없는 경우(예: 특정 프레임워크가 요구하는 메서드명)처럼 불가피한 경우가 아니면 예외를 두지 마세요. 불가피한 경우라면 왜 예외인지 상세설계 문서(15장 참고자료) 또는 코드 주석에 남기세요.

## 확인 방법

`tools-and-thresholds.md`의 `.pylintrc` 설정 후 `pylint --enable=invalid-name`을 실행해 경고가 없으면 통과입니다.
