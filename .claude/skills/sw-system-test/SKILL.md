# SW 시스템(자격) 테스트 케이스 생성 (SWE.6)

이 스킬은 "무엇을 근거로, 어떤 기법으로, 어떤 원칙으로" 시스템(자격) 시험 케이스를 설계할지에 대한 방법론만 정의합니다. 요구사항 분석, 사용자와의 확인, 실제 산출물(xlsx) 작성은 이 스킬을 사용하는 에이전트(`sw-system-tester` 서브에이전트)가 수행합니다.

테스트 베이시스는 **SW 요구사항 명세서 하나뿐**입니다 — 아키텍처 내부 구조나 코드를 보고 케이스를 만들지 마세요. 그것은 각각 `integration-testing`(SWE.5, 인터페이스 기준)과 `tdd`(SWE.4, 함수 내부 기준) 스킬의 범위입니다. 세 스킬의 정확한 경계는 `references/aspice-swe6.md`의 비교표를 참고하세요.

## 참조 파일

| 파일 | 언제 읽는가 |
|---|---|
| `references/template.md` | 항상 먼저 — 조직 검증 산출물 양식(TPL-SWE6-001/002)의 실제 구조를 확인할 때 |
| `references/technique-selection.md` | 기반지식(ISO 26262-6 Clause 11, A-SPICE SWE.6, ISO 29119/ISTQB, ISO 25000)과 기법 선택·PICT 도구 사용법을 확인할 때 |
| `references/aspice-swe6.md` | SWE.6 기본관행 대응과 SWE.4/SWE.5와의 경계를 확인할 때 |

## 작업 절차

1. **입력 확인 — 테스트 베이시스 확보.** 대상 SW 요구사항 명세서(`requirements-analysis` 스킬 산출물)를 확인합니다. 명세서 없이, 또는 코드/아키텍처를 근거로 케이스를 지어내지 마세요.

2. **환경 정의.** 검증 환경(SW-only PC/SIL, HIL, 실차 등), 버전, 수집 증거, 명시적으로 제외하는 시험 수준을 `references/template.md`의 TPL-SWE6-001 시트 2(환경 표)에 정의합니다. 이 프로젝트가 SW-only 검증이라면 "명시적 제외"에 그 경계를 정직하게 기록하세요.

3. **기법 선정과 케이스 설계.** `references/technique-selection.md`의 기법(경계값/동등분할/조합/페어와이즈/엣지케이스/경험기반) 중 요구사항 성격에 맞는 것을 선택해 TPL-SWE6-001 시트 1의 각 행을 작성합니다. 기능 요구사항과 비기능 요구사항(ISO 25000 품질특성별) 모두 같은 표에, `references/template.md`의 ID 접두사 규칙으로 구분해 작성합니다. 조합 폭발이 우려되면 PICT로 페어와이즈(또는 `/o:max`로 전수) 조합을 생성합니다.

4. **케이스 검토.** 예상 결과가 명세서에 없거나 더 엄격한 기준이 필요하면, 임의로 가정하지 말고 사용자에게 확인한 뒤 `[확정: ...]` 표기로 근거를 남깁니다. 명세서 근거 없이 QA 관점에서 제안하고 싶은 케이스는 "(제안)"으로 표시합니다.

5. **실행 및 결과 기록.** 케이스를 실행하고 TPL-SWE6-002(Test ID·SW Req·Result·Actual Result·Evidence Locator·Execution Time·Scope Note)를 채웁니다. 범위별 집계(계획/실행/Pass/Fail/미실행/판정/제한)를 시트 2에 남깁니다.

6. **완료 조건.** SW 요구사항 명세서의 모든 요구사항(기능+비기능)에 대응하는 케이스가 존재하고, 실행 결과가 기록됐으며, 명세서에 없는 판정기준이 전부 사용자 확인을 거쳐 `[확정: ...]`으로 남아있을 때 이 단계가 끝난 것입니다.

## 하지 말아야 할 것

- SW 요구사항 명세서 없이, 또는 코드/아키텍처를 직접 보고 케이스를 지어내지 마세요.
- 함수 내부 로직(SWE.4)이나 컴포넌트 간 인터페이스 계약(SWE.5)을 이 스킬에서 대신 검증하려 하지 마세요 — 발견한 문제는 기록하되 원인 분석은 해당 스킬로 넘기세요.
- 템플릿에 없는 시트나 열("확정 근거" 열 등)을 임의로 추가하지 마세요 — `references/template.md`가 정한 방식(셀 안 `[확정: ...]` 표기, ID 접두사)으로 대신하세요.
- 예상 결과를 임의로 가정하지 마세요.
- 의미 없이 케이스 수만 채우지 마세요 — 실행 가능하고 재현 가능한 케이스만 작성합니다.
