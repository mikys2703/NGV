# 시험 설계 기법 선택과 근거

## 기반지식

- **ISO 26262-6 Clause 11(소프트웨어 안전 요구사항 검증)**: 통합된 전체 소프트웨어가 SW 요구사항(및 그에 할당된 안전 요구사항)을 만족하는지 블랙박스로 검증하라는 요건입니다. ASIL 등급이 할당된 요구사항은 요구사항이 표현하는 조건 조합(경계값, 조합)을 빠짐없이 검증해야 합니다.

  > 정확한 절 번호와 문구는 조직이 보유한 라이선스 표준 원문(ISO 26262-6:2018)으로 검증하세요. Clause 9(단위 검증)는 `tdd`/`code-quality-gates` 스킬이, Clause 10(통합 시험)은 `integration-testing` 스킬이 각각 담당하므로, 이 스킬에서 그 절들의 요건을 다시 다루지 않습니다.
- **A-SPICE SWE.6**: 소프트웨어 자격시험(Software Qualification Test)의 Base Practice. 상세는 `references/aspice-swe6.md`.
- **ISO 29119 및 ISTQB**: 테스트 시나리오·테스트 케이스 설계 프로세스와 용어 체계(긍정/부정 분류 등)의 근거로 사용합니다.
- **ISO/IEC 25000 (SQuaRE)**: 비기능(품질) 요구사항을 분류하는 기준입니다. 비기능 케이스는 이 표준의 품질 특성(기능적합성/성능효율성/호환성/사용성/신뢰성/보안성/유지보수성/이식성)별로 태깅합니다(`references/template.md`의 ID 접두사 규칙).

## 적용 대상 테스트 기법

요구사항의 성격에 맞춰 아래 기법 중에서 선택하여 적용하고, 각 케이스의 `Technique` 열에 실제로 적용한 기법을 명시합니다.

- **경계값 분석**: 검증기준에 수치·범위·임계값이 있는 경우, 경계값 미만/경계값/경계값 초과를 각각 별도 케이스로 도출합니다.
- **동치 클래스(동등분할)**: 입력 도메인을 유효/무효 클래스로 나누어 대표값을 도출합니다.
- **조합 테스트(전 조건 조합)**: 관련 조건 수가 적어 전수 조합이 실행 가능한 범위일 때 우선 적용합니다.
- **페어와이즈**: 조건·값의 조합 수가 많아 전수 조합 테스트가 비현실적인 경우에 대체 적용합니다.
- **엣지 케이스**: 정상 범위의 극단, 동시성/타이밍 등 일반 분석 기법으로 포착되지 않는 특이 조건을 다룹니다.
- **경험 기반 테스트**: 유사 시스템의 결함 이력이나 QA 경험에 근거해 오류를 추정합니다(오류 추정, 탐색적 테스트 등).

## 도구 사용 — PICT

- 페어와이즈 조합을 생성할 때는 오픈소스인 PICT를 사용합니다.
- 전수 조합(모든 조건의 조합)을 생성할 때는 PICT의 `/o:max` 옵션을 사용합니다.

## 작성 원칙

- 의미 없이 커버리지 수치 달성만을 목적으로 하는 케이스는 생성하지 않습니다.
- 예상 결과를 임의로 가정하지 않습니다. 명세서에 근거가 없다면 이 스킬을 사용하는 에이전트가 사용자에게 확인을 받아, `references/template.md`의 `[확정: ...]` 표기로 남깁니다.
- 기법 선택이나 범위 설정이 판단하기 어려운 경우 임의로 결정하지 말고, 사용자 검토를 받습니다.
- 명세서에 직접적 근거는 없으나 QA 관점에서 추가를 제안하고 싶은 케이스는 `Test ID` 또는 케이스명 끝에 "(제안)"이라고 표시해 구분합니다.
- 실행자가 그대로 재현할 수 있는, 실행 가능한 케이스만 작성합니다.
